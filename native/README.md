# Optional native desktop access

This module controls the real OS desktop. It is separate from Folklet's per-bot browser and is disabled at every host startup. Enable it explicitly for the current session. Each model screenshot or input requires a fresh user approval; model input cannot select its own approval or actor. Screenshots are sent to the selected model provider. The module keeps only the latest screenshot in memory and does not save typed values or screenshots. Temporary macOS captures are removed immediately.

The desktop is shared by every local app and bot. This is not a virtual machine or a system security boundary. Keep the desktop unlocked, review the proposed action, and avoid simultaneous human/agent input. Input must use the latest screenshot's `frameId`; frames expire after one minute. A screenshot is taken after each approved action. Disable access to cancel pending approvals and queued actions. Already delivered OS input cannot be undone by disabling the module.

## Platforms

- **Windows x64:** the included C# helper uses .NET Framework, primary-display capture and `SendInput`. Build with `native/Build-Windows.ps1`. No administrator launch, driver installation or execution-policy change is needed. Elevated apps, UAC/secure desktops and locked/noninteractive sessions are unsupported. The helper was compiled on Windows; desktop actions were tested only with mocks.
- **macOS:** build the helper on macOS with Apple command line developer tools: `sh native/Build-macOS.sh --arch arm64` or `--arch x64`. This creates `macos-control-arm64` or `macos-control-x64`. Package only the matching architecture as `native/macos-control` and retain executable permission. If no compiled helper is included, native access is unavailable until a native build is supplied. Grant Screen Recording and Accessibility to Folklet/the responsible helper in System Settings when requested by macOS; Folklet does not grant or bypass those permissions. Capture and input use the primary display. This helper has not been compiled or exercised on a Mac in this Windows development environment.
- **Linux:** use an unlocked local **X11** desktop with `xdotool` and ImageMagick's `import` installed by the administrator. `DISPLAY` must be local, such as `:0` or `:1`. Wayland, SSH-forwarded displays, lock screens and a bare headless shell are unsupported. An isolated desktop inside a VPS/VM can provide an X11 session; this module does not create or expose a desktop, install packages, open ports or grant system privileges. Keyboard behavior still depends on the desktop keymap. Linux actions were tested only with mocks.

## Integration

`new NativeComputer()` starts disabled. `status()` is read-only and captures nothing. `setEnabled(boolean)` is for the authenticated local settings endpoint; do not expose it as an agent tool. `execute(bot, action, approve)` invokes model access, where `approve(request)` must return the boolean `true` after a real user decision. Explicit manual UI controls may use `act(action, {actor:'user'})`; that actor must come from trusted host code, never the request body.

Actions are `look`, `click`, `type`, `key`, and `scroll`. Every non-look action needs `frameId`. Click coordinates use screenshot pixels; the adapter maps them to actual display coordinates. Scroll `delta` is 1–10 wheel ticks, positive down and negative up. Shortcuts use `Control`, `Alt`, `Shift`, `Meta`, letters/digits, and named keys such as `Enter` or `ArrowLeft`. Results contain `frameId`, PNG `image` in base64, `mimeType`, `width`, `height`, and `capturedAt`.
